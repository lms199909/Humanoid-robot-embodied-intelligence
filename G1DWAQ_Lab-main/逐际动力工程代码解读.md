### 2.2 核心文件详解

#### `deploy.py` (L13-305) — `Controller` 类

这是部署的"心脏",**3 个线程**协作:

| 线程 | 频率 | 职责 |
|---|---|---|
| `run_thread` | 50/100 Hz(由 `control_dt` 决定) | 读状态 → 构造 obs → 推 policy → 写目标位置 |
| `publish_thread` | **500 Hz** | 把 `low_cmd` 持续发到电机(高频保活) |
| 主循环 | 10ms 轮询 | 监听 `Select` 按钮,触发时退出 |

**生命周期**(L48-129):

```
__init__()
  ├─ ChannelFactoryInitialize(0, net)     # 初始化 DDS
  ├─ torch.jit.load(policy_path).eval()   # 加载 TorchScript
  ├─ 50 次 warm-up policy forward         # JIT 预热
  ├─ 创建 LowCmd/LowState 的 Publisher/Subscriber
  ├─ wait_for_low_state()                 # 等 DDS 握手成功
  ├─ init_cmd_hg() 或 init_cmd_go()       # 初始化控制帧
  ├─ publish_thread.Start()               # 启动 500Hz 发布
  ├─ wait_for_start()                     # 等手柄 Start 键
  ├─ move_to_default_pos()                # 2s 缓动到 default_joint_pos
  ├─ wait_for_control()                   # 等手柄 A 键
  └─ run_thread.Start()                   # 启动主控循环
```

**观测构造** `Controller.run()`(L221-277)是核心逻辑:

```python
# 简化的 obs 拼装顺序(63 维 num_obs = 3 + 3 + 3 + 23 + 23 + 23 + 4)
current_obs[0:3]   = ang_vel                          # IMU 角速度
current_obs[3:6]   = gravity_orientation              # 投影重力到机体
current_obs[6:9]   = command                          # 手柄指令(vx,vy,ωz)
current_obs[9:32]  = joint_pos - default_joint_pos    # 关节位置偏差
current_obs[32:55] = joint_vel                        # 关节速度
current_obs[55:78] = action (last step)               # 上一步动作
current_obs[78:82] = gait_phase [可选]                # 4 维:左右腿 sin/cos 相位
```

obs 拼好后:
1. 维护 `current_obs_history`(长度 = `history_length`,默认 10),FIFO 更新
2. 展平历史 → `obs_history.reshape(1, -1)` → 喂给 `self.policy(...)`
3. policy 输出 `action` → `target_dof_pos = default_joint_pos + action * action_scale`
4. 把目标位置写到 `low_cmd.motor_cmd[joint2motor_idx[i]].q`

**安全退出** `stop()`(L140-148):按下 Select 键,先发 `create_damping_cmd`(kp=0, kd=10),再 `sys.exit(0)`。

#### `config.py` (L1-65) — `Config` 类

YAML 配置加载,无继承无方法,纯 dataclass 风格:

| 字段 | 类型 | 含义 |
|---|---|---|
| `control_dt` | float | 主循环周期(0.02 = 50Hz, 0.01 = 100Hz) |
| `msg_type` | str | `hg`(G1 用) / `go`(H1/Go2 等) |
| `imu_type` | str | `torso`(腰 IMU) / 其他(头 IMU) |
| `weak_motor` | list | 宇树 G1 弱电机索引(只支持 PR 控制) |
| `lowcmd_topic` / `lowstate_topic` | str | DDS topic |
| `policy_path` | str | TorchScript 模型路径 |
| `joint2motor_idx` | list[int] | 关节 → 电机索引映射(关键!G1 URDF 顺序跟策略动作顺序可能不同) |
| `kps` / `kds` | list[float] | 各关节 PD 刚度 / 阻尼(部署侧固定) |
| `default_joint_pos` | list[float] | 默认站姿关节角 |
| `ang_vel_scale` / `dof_pos_scale` / `dof_vel_scale` / `action_scale` | float | obs/action 的归一化缩放系数 |
| `command_scale` | list[float] | [lin_vel_x, lin_vel_y, ang_vel_z] 的最大幅值 |
| `num_actions` / `num_obs` | int | obs/action 维度 |
| `history_length` | int | obs 历史长度(默认 10) |
| `command_range` | dict | 每条指令的 [min, max] |
| `gait_phase` (可选) | dict | `enable / period / offset` |

#### `common/command_helper.py` (L17-75) — 命令构造工具

4 个纯函数,无状态,只构造 `LowCmd_`:

| 函数 | 作用 |
|---|---|
| `MotorMode.PR = 0` / `MotorMode.AB = 1` | 电机控制模式常量(PR=串联,Pitch/Roll 关节;AB=并联,A/B 关节) |
| `create_damping_cmd(cmd)` | 全部电机 kp=0, kd=10(被动阻尼,急停用) |
| `create_zero_cmd(cmd)` | 全部归零(基本不用) |
| `init_cmd_hg(cmd, mode_machine, mode_pr)` | 初始化 HG 协议 LowCmd(G1 用) |
| `init_cmd_go(cmd, weak_motor)` | 初始化 GO 协议 LowCmd(设 head、level_flag、gpio;弱电机 mode=1,其他 mode=0x0A) |

**`weak_motor` 机制**:G1 的"弱电机"(无力矩传感器)必须用 PR 模式(Series Control),其他用 AB 模式(Parallel Control)。

#### `common/remote_controller.py` (L15-50) — `RemoteController` 类

手柄输入解析。`set(data)` 把 32 字节的 `wireless_remote` 字段解成 16 个按键 + 4 个摇杆:

```python
# 字节布局(从 deploy.LowStateHandler 调 self.remote_controller.set(self.low_state.wireless_remote))
data[0:2]   = header      # 忽略
data[2:4]   = keys        # uint16,bit0~15 对应 16 个按键
data[4:8]   = lx (float)  # 左摇杆 X
data[8:12]  = rx (float)
data[12:16] = ry (float)
data[20:24] = ly (float)
```

`KeyMap` 类定义按键编号(0=R1, 1=L1, 2=start, 3=select, 4=R2, 5=L2, 6=F1, 7=F2, 8=A, 9=B, 10=X, 11=Y, 12~15=方向键)。

#### `common/rotation_helper.py`

两个工具函数:
- `get_gravity_orientation(quat)`:把世界系重力 `(0,0,-1)` 通过 `quat` 转到机体系,得到 3 维向量(供 obs 用)
- `transform_imu_data(waist_yaw, waist_yaw_omega, imu_quat, imu_omega)`:把头 IMU 数据通过腰部 yaw 关节补偿,得到"全机姿态"

### 2.3 部署数据流

```
[Unitree 真机]
   │  DDS LowState_ (1kHz)
   ▼
ChannelSubscriber("lowstate")
   │  LowStateHandler(msg)
   ▼
remote_controller.set(wireless_remote)         # 解手柄
joint_pos[i] = low_state.motor_state[idx].q    # 读位置
joint_vel[i] = low_state.motor_state[idx].dq   # 读速度
quat = low_state.imu_state.quaternion          # 读 IMU
   │
   ▼
Controller.run() [50/100 Hz]
   │
   │ 构造 current_obs (63 维)
   │ 拼 current_obs_history (10 × 63)
   │
   ▼
self.policy(torch.from_numpy(obs))              # TorchScript
   │  action (num_actions,)
   ▼
target_dof_pos = default + action * action_scale
   │  写 low_cmd.motor_cmd[idx].q
   ▼
Controller.publish() [500 Hz]  ──  DDS LowCmd_  ──  [Unitree 真机电机]
```

### 3.2 核心文件详解

#### `legged_lab/envs/base/base_env.py` (L30-330) — `BaseEnv(VecEnv)`

所有具体任务环境(G1Env / H1Env / TienKungEnv / OliEnv)的基类。**继承 rsl_rl.env.VecEnv**——这是 RSL-RL 的"并行环境"抽象,内部持有 `num_envs` 个仿真。

**初始化流程**(`__init__`, L31-84):

```
1. 读 cfg(BaseEnvCfg)+ headless 标志
2. 构造 SimulationContext (Isaac Sim)
   - dt = cfg.sim.dt (e.g. 0.005s = 200 Hz 物理)
   - decimation = cfg.sim.decimation (e.g. 4 → 50 Hz 控制)
3. 构造 InteractiveScene(cfg.scene)
   - 包含 robot (Articulation) + terrain + sensors
4. 构造 UniformVelocityCommand (随机速度指令生成器)
5. 构造 RewardManager(cfg.reward)
6. init_buffers():
   - 申请 obs/action/history 缓冲
   - 构造 DelayBuffer (action delay 域随机化)
   - 解析 SceneEntityCfg(机器人 / 接触部位)
7. EventManager 触发 startup 事件(物理参数初始化)
8. reset(env_ids) 第一次
```

**核心方法签名**:

```python
class BaseEnv(VecEnv):
    def reset(self, env_ids: torch.Tensor) -> tuple[torch.Tensor, dict]:
        """重置指定 env_ids,返回 (obs, info)"""
        ...

    def step(self, actions: torch.Tensor) -> tuple[torch.Tensor, torch.Tensor, torch.Tensor, dict]:
        """主步进:返回 (obs, reward, done, info)
        actions 形状: (num_envs, num_actions)
        """
        ...

    def get_observations(self) -> torch.Tensor:
        """构造策略 obs(本体感知 + 历史)"""
        ...

    def get_privileged_observations(self) -> torch.Tensor | None:
        """构造 critic obs(含特权信息:摩擦/质量/接触力等)"""
        ...

    def _update_history(self) -> None:
        """FIFO 更新 obs_history(长度 = actor_obs_history_length)"""
        ...
```

**域随机化**通过 `self.event_manager.apply(mode="reset")` 触发——在每个 env 复位时,随机化物理参数(质量、摩擦、电机强度、IMU 噪声等)。

**`DelayBuffer`**:在 env 内部模拟"动作延迟"——即策略输出的 action 不是立即生效,而是延迟 N 步再发到电机。这是为了 sim2real 鲁棒性。

四种算法:

| 算法 | 适用 | 特点 |
|---|---|---|
| **PPO** | 标准步态 | On-policy actor-critic + GAE |
| **DWAQ-PPO** | DWAQ(Discriminator-Weighted Actor-Q) | AMP 风格,判别器提供"自然度"奖励,见 `docs/DWAQ_LATENT_CODE.md` |
| **AMP-PPO** | AMP(Adversarial Motion Priors) | 同 DWAQ 但用更直接的对抗奖励 |
| **Distillation** | 学生-教师蒸馏 | 把 DWAQ 策略蒸馏到紧凑学生网络,便于部署 |

**DWAQ** 是这个项目的特色——把"判别器对参考运动库的似然"作为额外奖励,让策略学会更自然的步态。详见 `docs/DWAQ_LATENT_CODE.md`。

#### `rsl_rl/rsl_rl/algorithms/ppo.py` (未读,基于 PPO 标准)

PPO 主算法,核心方法:

```python
class PPO:
    def __init__(self, env, cfg, device): ...

    def learn(self, num_learning_iterations: int):
        """主训练循环:
        for it in range(num_learning_iterations):
            rollout = self.play_rollout()      # 收集 num_steps_per_env 步
            returns, advantages = self.compute_returns_and_advantages(rollout)
            for epoch in range(num_epochs):
                for batch in self.mini_batches(rollout):
                    self.update(returns, advantages, batch)  # PPO clip loss + value loss + entropy
        """

    def update(self, returns, advantages, batch):
        """单次 PPO 更新:
        - 计算 ratio = exp(logp_new - logp_old)
        - L_clip = min(ratio * A, clip(ratio, 1-eps, 1+eps) * A)
        - L_value = (V - returns)^2
        - L_entropy = -H(π)
        - L = -L_clip + value_coef * L_value - entropy_coef * L_entropy
        """
```

#### `rsl_rl/rsl_rl/algorithms/dwaq_ppo.py` (未读,基于 PPO + AMP)

DWAQ 在 PPO 基础上加:
1. 判别器网络(基于 motion reference 库训练)
2. 判别器奖励:`r_amp = -log(1 - D(s, s'))`(D 越确信(s,s')来自 reference 越像,奖励越高)
3. **潜在码**(latent code,见 `docs/DWAQ_LATENT_CODE.md`):把判别器中间层输出作为"风格表征"喂给 actor,让策略学会"多种风格"

DWAQ 训练时除了策略梯度,还要**更新判别器**(区分 expert motion vs 当前策略 motion)。

### 3.3 训练数据流

```
[TienKung-Lab/scripts/train.py]
  │ 解析 cfg,构造 BaseEnv(MultiTask)
  │ 构造 Runner(OnPolicyRunner / AMPOnPolicyRunner / DWAQOnPolicyRunner)
  │ runner.learn(num_iterations=1000)
  ▼
[每 iteration]
  │
  ├─ rollout: 4096 envs × num_steps_per_env 步
  │   │
  │   │ BaseEnv.step(action)
  │   │   ├─ 物理步进 (Isaac Sim 200Hz)
  │   │   ├─ 计算 obs / reward / done
  │   │   ├─ EventManager.apply("reset") on done envs
  │   │   └─ update obs_history
  │   │
  │   ▼
  │   rollout 缓冲 (obs, action, log_prob, value, reward, done)
  │
  ├─ compute GAE advantages
  │

  │
  ▼
[每 N iteration] save checkpoint to logs/<task>/<timestamp>/model_<N>.pt
```

### 4.2 核心模块详解

#### `core/channel.py` — DDS 通道管理

```python
class ChannelFactory:
    """进程级单例:管理 DDS 域 ID + 网络接口"""
    @staticmethod
    def Init(domain_id: int, interface: str):
        """指定域 ID 和网卡(如 'eth0' / 'eno1' / 'wlan0')"""
        ...

class ChannelPublisher:
    def __init__(self, topic_name: str, msg_type):
        """声明一个发布者,msg_type 是 IDL 类"""
        ...
    def Init(self):
        """初始化底层 DDS writer"""
        ...
    def Write(self, msg):
        """发布一条消息"""
        ...

class ChannelSubscriber:
    def __init__(self, topic_name: str, msg_type):
        ...
    def Init(self, handler, queue_size: int = 10):
        """订阅 + 注册回调(异步,handler 在另一个线程被调)"""
        ...
```

**关键设计**:
- 同一进程内 `ChannelFactory` 单例,所有 Publisher/Subscriber 共享
- Subscriber 的 handler 在独立线程调(不是 ROS 那种 spin)
- `queue_size=10` 是 DDS 内部队列,满了会丢

#### `idl/unitree_go/` vs `idl/unitree_hg/`

两套**协议版本**:
- **GO 协议**(`unitree_go`):B2 / Go2 / H1 老协议。`LowCmd_` 含 20 字节头(head + level_flag + gpio + 保留位),电机指令用 32 字节打包。
- **HG 协议**(`unitree_hg`):G1 / H1_2 新协议。`LowCmd_` 头部简化,电机指令 16 字节,新增 `mode_machine` / `mode_pr` 字段。

部署选哪个协议看 `config.msg_type`:
- `msg_type = "hg"` → G1 / H1_2
- `msg_type = "go"` → Go2 / B2 / H1

**`lowcmd_topic` / `lowstate_topic`** 默认值取决于协议。

#### `g1/` 子包 — G1 业务 API

G1 比 Go2/H1 多一些专属业务:

| 模块 | 作用 |
|---|---|
| `g1/loco/` | `G1LocoClient` — 全身步态 high-level(走 rt/rtl 模式) |
| `g1/arm/` | `G1ArmActionClient` — 手臂动作(7-DoF 臂控制) |
| `g1/audio/` | `G1AudioClient` — 麦克风/扬声器 |

**`G1LocoClient` 跟 `LeggedLabDeploy` 的关系**:
- `G1LocoClient` 是 high-level API(SDK2 自己内置的步态)
- `LeggedLabDeploy` 是 low-level API(自己训的策略)
- 两者**互斥**:同一时间只能用一种

## 7. 关键工程经验(从代码风格反推)

读这些代码能提取出对 `Project/` 的设计启发:

1. **观测/动作的尺度归一化(`*_scale`)很关键** — 不同物理量纲差异大,统一缩放到 ~1 量级
2. **历史观测(`history_length=10`)是经验值** — 太短缺信息,太长训练慢
3. **DWAQ 比标准 PPO 在自然度上更好** — 见 `docs/DWAQ_vs_Standard_Analysis.md`
4. **域随机化(DR)是 sim2real 关键** — 质量 ±20%、摩擦 ±50%、动作延迟、IMU 噪声
5. **`weak_motor` 区分是 G1 的硬约束** — 弱电机只能 PR 模式,别让它走位置控
6. **500Hz publish 是为了 PD 闭环稳定** — 算法 50Hz,但下发频率要远高于控制频率
7. **CRC 是宇树消息的硬要求** — 每条 LowCmd_ 必须算 CRC
8. **`policy.eval()` + `torch.inference_mode()`** — 部署时关闭梯度,JIT 友好
9. **50 次 warm-up policy forward** — 启动时预热,避免首次控制卡顿
10. **关节 → 电机索引映射**(`joint2motor_idx`)是常见的 URDF 重排需求,部署侧必须有

## 9. 已知限制 / 注意事项

1. **`unitree_sdk2py` 只支持 Unitree 机器人** — 给 LimX Oli 用需要替换 SDK 层
2. **`legged_lab/envs/oli/`** 这里的 `oli` 任务**不是** LimX Oli(没看完整代码前要确认,可能是 G1 的 oli 变体命名)
3. **G1DWAQ 是 sim2real 的"模板"** — 不一定直接适配所有机器人,关节 / 动力学 / 控制器可能需要重写
4. **DWAQ 依赖 motion reference 库** — 需要先有"参考运动数据"(如真人步态 mocap)
5. **大规模训练(4096 envs)需要强 GPU** — Isaac Lab 对显存要求高,部署侧轻量
